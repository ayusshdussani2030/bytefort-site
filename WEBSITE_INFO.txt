HEALTH CHECK WORKER
-------------------
Worker name: bytefort-metrics
Entry point: worker/worker.js
Binding: BYTEFORT_UPTIME (KV namespace)

Endpoints:
  GET /health  — Live health check for all services
  GET /metrics — Alias for /health
  GET /uptime  — Historical uptime data from KV
  GET /        — Alias for /health

Health Check Logic:
  - Checks all 9 services every 5 minutes via cron
  - Only writes to KV when a service's status changes
  - No heartbeat, no expiration, no list/delete
  - Maximum ~288 KV writes/day (one per 5-min window if all flip)
  - Current config uses ~1-5 writes/day in practice

Uptime Tracking:
  - Version 2 schema with cumulative uptime accounting
  - Tracks trackingStart, statusSince, totalUptimeMs per service
  - Retains past downtime after recovery
  - Estimates continuation of last recorded state between checks
  - Dashboard ticks locally without extra KV writes

KV Schema (status key):
  {
    version: 2,
    checkedAt: "ISO-8601 timestamp",
    services: { ServiceName: "online" | "offline", ... },
    accounting: {
      ServiceName: {
        trackingStart: "ISO-8601",
        statusSince: "ISO-8601",
        totalUptimeMs: number
      }, ...
    }
  }

MAINTENANCE GATE WORKER + ADMIN PANEL
--------------------------------------
Separate from the health check worker above — this one fronts bytefort.xyz itself.

Worker name: bytefort-site
Entry point: maintenance-worker/worker.js
Binding: BYTEFORT_MAINT (KV namespace)
Admin password: set via `wrangler secret put ADMIN_PASSWORD` (never hardcoded)

Pages served by the worker:
  /admin        — admin/index.html (password-gated, X-BF-Protected, no-store)
  (maintenance) — maintenance/index.html, served in place of any page while
                  maintenance mode is enabled

Admin API (under /api/bf, requires X-BF-Secret header except login/status):
  POST /admin/login              — validate password, returns token
  POST /maintenance/toggle       — enable/disable maintenance mode
  POST /maintenance/message      — update maintenance message/ETA
  POST /maintenance/services     — set partial-maintenance target services
  GET  /maintenance/status       — public; polled by index.html + maintenance page

Rate limit: 10 requests/min per route (in-memory, per Worker isolate).

INTERACTIVITY (script.js)
-------------------------
1. Boot intro overlay — fills progress bar, cycles status text
2. Typing animation — cycles taglines with typing/deleting effect
3. Service cards — generated dynamically with renderCards()
4. Health check — polls api.bytefort.xyz/metrics every 30s
5. Historical uptime — fetches /uptime, ticks locally every second
6. Scroll progress bar — fixed top bar tracks page scroll
7. Mouse glow — radial gradient follows cursor
8. Hero canvas — 85-particle network with mouse repulsion
9. Animated counters — numbers count up when scrolled into view
10. Navbar — scroll state changes, active link tracking
11. Scroll reveal — elements fade in with stagger on scroll
12. 3D card hover — perspective transform on mouse move
13. Service filter — category-based grid filtering
14. Mobile menu — hamburger toggle with full-screen overlay
15. Toast notifications — clipboard copy with 2.2s display
